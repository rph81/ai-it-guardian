Connectors

A scan sees devices from the outside. A connector lets Guardian look inside with a read-only account you create, for checks like patch levels, backup status, user accounts and shares. Nothing is ever changed.

The vault is locked

Connectors and their passwords are encrypted. Unlock with your passkey to see and use them.

AI agents

After the network scan, a team of Claude agents analyses the results. Each specialist looks at one part of your IT, can only run the read-only checks listed on its card, and writes findings into the report. The Orchestrator assigns the work, passes notes between agents and answers your questions in the console chat.

How an assessment runs

  1. Network scan program Finds devices, ports, services, web pages, certificates, UPnP and what the internet sees. No AI, free.
  2. Discovery AI agent Works out what every device is: type, vendor, model, role, OS and firmware.
  3. Orchestrator AI agent Decides which specialist looks at which devices, relays notes between agents and instructions from the chat.
  4. Specialists AI agents, a few at a time Network, OS & endpoints, Web & APIs, Firmware, Internet perimeter. When one finds something another should check, it sends that agent a note.
  5. Report writer AI agent Scores the site, writes the summary and the fix-first list in plain language.

The agents

Keys are write-only: the console never shows or returns them.

What agents can never do

  • No shell, no commands. Agents only call the fixed checks on their cards.
  • Your network only. Every address is checked against the scanned network before a probe runs.
  • No logins, no changes. Web requests are GET/HEAD without credentials; probes are non-intrusive. The chat can't change anything either.
  • No access to the vault. Agents never see connector passwords or your API key.

Security & vault

Connector passwords, tokens, keys and API keys are in an encrypted vault. It opens only when an admin or operator confirms with their passkey, and closes when they sign out or go idle.

How your secrets are protected

Your passkeyLives on your device (Face ID, Windows Hello, YubiKey) and never leaves it.
Your personal keyOpened only by your passkey. Stored encrypted; useless without it.
Vault keySealed separately for each admin and operator. Never written to disk unencrypted.
Each secretEncrypted on its own (AES-256-GCM) and bound to its record.

While the vault is locked, someone with full access to the server, including an AI tool, sees only encrypted data.

Recovery key

Opens the vault if every admin passkey is lost. Guardian keeps only an encrypted copy of the vault key under it.

Schedules & alerts

Run scans automatically and get told when something changes.

Schedules

Times are the server's local time. A scheduled run doesn't start while another run is going; it waits up to an hour.

Scheduled AI runs while the vault is locked

The Anthropic key normally lives only in the vault, which is locked when nobody is signed in, so a scheduled AI assessment at night can't use it and runs a scan instead (and tells you). If you allow it, Guardian keeps a copy of the key in a file only the server's root account can read, like the sign-in provider secrets. Anyone with root access to the container could then read the key. You can switch this off at any time; the copy is deleted.

Alerts

Sent after every run that finishes (scheduled or started by hand). Webhook addresses and the e-mail password are needed when nobody is signed in, so like the sign-in provider secrets they're protected by the server's file permissions rather than the vault.

Evidence library

Ticketing

          
Guardian opens one ticket per finding in your ticketing system, keeps it across assessments, reads its state back into the Fix plan, and adds a note (optionally closes it) when a re-check verifies the fix. Use a dedicated API user. Its secret is needed after scheduled runs, so like the alert secrets it's protected by the server's file permissions.
