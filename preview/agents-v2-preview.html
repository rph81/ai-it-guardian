Agents / v2.

Seven new agent categories, each modelled on what the market leaders sell, plus four platform features they need. All read-only, like today's agents. New agents and features are marked new.

Guardian / run order

How a run flows.

1 · ScanNetwork scanner (unchanged)
2 · DiscoveryIdentifies every device (unchanged)
3 · SpecialistsToday's 5 + Active Directory, Microsoft 365, Patch & config, Device fleet, in parallel
4 · Risk analystRanks every finding by real-world exploitation
5 · Attack pathsChains findings into paths, finds choke points
6 · ComplianceMaps everything to CIS, ISO 27001, NIS2, nLPD; then the report

Agents that need a connector only run when it's set up; the map and Settings > AI agents show them as "needs connector" otherwise.

Guardian / new agent categories

New agents.

newcriticalspecialist

Active Directory

Finds the identity weaknesses attackers use to take over a Windows domain, by reading the directory only.

Modelled on
Tenable Identity Exposure; the AD checks in Pentera and Horizon3 NodeZero (without attacking)
Needs
Active Directory connector (exists: a normal domain user over LDAPS)
Tools
ldap_query with a fixed list of read-only queries
  • Accounts open to Kerberoasting / AS-REP roasting
  • Unconstrained or risky delegation
  • Too many or stale admins, admins with non-expiring passwords
  • Old krbtgt password, no LAPS, weak password and lockout policy
  • End-of-life domain controllers, risky trusts
newcriticalspecialist

Microsoft 365 & Entra ID

Checks the cloud tenant where small businesses actually get breached: sign-in, admins, mail and apps.

Modelled on
Microsoft Secure Score / Defender CSPM, Tenable Identity Exposure (Entra), Qualys SaaS posture, CIEM
Needs
New Microsoft 365 connector: an app registration with read-only Graph permissions (certificate sign-in)
Tools
graph_get limited to a list of read-only endpoints
  • Users without MFA, legacy authentication still allowed
  • Global admins: how many, MFA, standing access
  • Conditional Access gaps, security defaults off
  • Mail forwarding to outside addresses, risky inbox rules
  • Guests, over-privileged third-party apps and consents, Secure Score trend
newcriticalspecialist

Patch & configuration

Logs in read-only and checks what a scan from outside can't see: missing patches, outdated software, hardening.

Modelled on
Nessus credentialed scans, Qualys VMDR + Policy Compliance, Rapid7 InsightVM, CIS Benchmarks
Needs
Linux SSH, Synology, Proxmox connectors (exist); new Windows (WinRM) connector
Tools
host_command from a fixed list of read-only commands per OS; connector_data
  • Missing security updates, matched to KEV and EPSS
  • End-of-life OS and software, full software inventory
  • CIS-style checks: SSH, firewall, disk encryption, antivirus, local admins, SMB settings
newhighspecialist

Device fleet

Covers laptops and phones that are rarely on the office network, through the tools that already manage them.

Modelled on
Tenable / Qualys / Rapid7 agents, CrowdStrike Falcon exposure, Defender Vulnerability Management
Needs
Microsoft 365 connector (Intune; Defender for Business if licensed)
Tools
graph_get (devices, compliance, Defender vulnerabilities)
  • Devices not compliant, not encrypted, out of date, not checked in
  • Antivirus / EDR off or missing
  • Vulnerable software on laptops, by device
newcriticalanalyst

Risk analyst

Re-ranks every finding by how likely it is to be used against this business, not just by severity.

Modelled on
Tenable VPR, Qualys TruRisk, Rapid7 Active Risk
Needs
Nothing: public feeds
Tools
epss_lookup (FIRST.org), kev_details incl. ransomware use, set_priority
  • Priority 1–4 per finding from KEV, EPSS, exposure and device importance
  • Merges duplicates across agents
  • "Fix these 5 first" with the reason for each
newhighanalyst

Attack paths

Chains findings into realistic paths to the business's crown jewels and names the fixes that break the most paths.

Modelled on
Tenable One attack paths, Wiz toxic combinations, NodeZero / NetSPI attack narratives (reasoned, not exploited)
Needs
Nothing: uses all findings and the network map
Tools
list_findings, inventory, record_path
  • Top attack paths, each step tied to a finding
  • Choke points: one fix that breaks several paths
newcriticalanalyst

Compliance

Turns the assessment into audit evidence: which controls are met, partly met or missing, with the proof.

Modelled on
Qualys Policy Compliance, Defender regulatory dashboard, PTaaS compliance reports
Needs
Nothing: control lists ship with Guardian
Tools
control_catalog, list_findings, set_control
  • CIS Controls v8 IG1, ISO 27001:2022 Annex A, NIS2 Art. 21, Swiss nLPD (data security)
  • "Not assessed" when Guardian has no way to see it, so nothing is overstated

Guardian / build order

Build in three waves.

Wave 1 · no new connectors needed

Risk analyst, Attack paths, Compliance agents; schedules & change alerts; notifications; remediation tracking with re-check. Works on every run from day one.

Wave 2 · connectors that already exist

Active Directory agent (AD connector); Patch & configuration agent for Linux, Synology and Proxmox.

Wave 3 · new connectors

Microsoft 365 connector + Microsoft 365 & Entra ID agent + Device fleet agent; Windows (WinRM) connector feeding Patch & configuration; first ticketing integration.

Same rules as today: every new tool is read-only and limited to a fixed list of queries or commands; you create the accounts and enter the secrets yourself; each new agent can be switched off and scaled in Settings › AI agents.

For you to decide: (1) Is this lineup and order right? (2) Notifications: which channels first (e-mail, Teams, Slack, webhook)? (3) Ticketing: which system first (Jira, ServiceNow, Autotask, ConnectWise), or leave it for later? (4) Several customers in one console (multi-tenant) is also critical for the MSP business, but it changes the structure of everything; I'd do it as its own step after these waves. Agree?
