Guardian / safety switch

Remediation / Status.

OFF
Guardian is read-only. No device can be changed.
  • Admin only, confirmed with a fresh passkey every time it's turned on.
  • Each change needs its own approval. Nothing runs in bulk.
  • Separate write accounts, stored apart in the vault and unlocked only while this is on. Read-only connectors never change anything.
  • Instructions found on devices or web pages can never trigger a fix: only the fixed recipes below exist.
Guardian / always manual

Never / Automatic.

Too risky to automate until a recipe is proven on that device. Guardian gives you step-by-step instructions instead.

  • Firmware flashes: a failed flash can brick the device.
  • Router WAN and firewall rules: one mistake cuts the whole site off.
  • The SSH or admin path Guardian itself connects through: it could lock itself (and you) out.
  • Anything on a device without a backup method.
For your customers

Each client signs a remediation authorisation and sets a change window. Every fix produces a change record (before, after, who approved, evidence) for their compliance file.

Low riskRecipe: router.upnp.disableTested on: supported router models

Turn off UPnP on the router

Device
Router 192.168.1.254 (model from the scan)
Why
UPnP let devices open 8 ports to the internet, including BitTorrent on the NAS (F004, high).
Change
Set UPnP = off through the router's admin API, using the write account guardian-fix.
Could break
Game consoles and some video-call apps may need manual port forwards. Nothing else on this network uses UPnP today (checked in the last scan).
Backup first
Full router config export, stored encrypted in the vault.
Rollback
Automatic if the router stops answering within 2 minutes; otherwise one click (restores the export).
Then
The Internet perimeter agent re-checks the forwards and closes F004 if they're gone.
