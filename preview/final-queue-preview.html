Guardian / Remaining queue

Everything left, in one plan.

Four build blocks in your order, then the final testing phase. Everything stays read-only except what already needs your passkey. Two items stay out on purpose (bottom of the page).

1 · Business systems

SAP and other platforms: three new connectors and one agent

SAP S/4HANA / ECC (on-premise)

Read-only technical user over HTTPS (SOAP RFC, table reads only). No SAP GUI, no RFC SDK to install.
  • Default users (SAP*, DDIC, EARLYWATCH, TMSADM) active or with known passwords' hash type
  • Users with SAP_ALL / SAP_NEW, dialog users not used for 90 days, old password hashes
  • RFC destinations that store passwords; trusted systems
  • Security audit log and key login/* profile parameters
  • Component versions vs SAP's latest support packages (missing security patches)

SAP BTP

Read-only service key for the BTP APIs (subaccount viewer, audit log reader).
  • Global and subaccount admins, users without MFA at the identity provider
  • Trust configuration (default identity provider still active)
  • Destinations with basic auth or no TLS
  • Audit log retention, Cloud Connector exposure

Salesforce

Connected app with read-only API access.
  • Salesforce Health Check score and risky settings
  • Admins, users without MFA, guest-user access on sites
  • Connected apps and their permissions

A new Business systems agent works through these, like the Azure and Microsoft 365 agents. Findings go into the same Fix plan, ATT&CK mapping, compliance map (ISO 27001, NIS2) and tickets. Other platforms (Workday, Oracle, ServiceNow security) can follow the same pattern later.

3 · Cloud

AWS posture agent

  • Read-only cross-account IAM role (SecurityAudit + ViewOnlyAccess), external ID; no access keys stored if you use the role
  • Root account MFA and keys, IAM users without MFA, old keys, wildcard policies
  • Public S3 buckets, security groups open to the internet, public snapshots and AMIs
  • CloudTrail, GuardDuty, Config and Security Hub turned on; KMS and encryption at rest
  • CIS AWS Foundations benchmark in the compliance map

Same pattern as the Azure agent: fixed list of read-only API calls, no free-form access. Findings get priority, ATT&CK techniques and tickets like everything else.

5 · Final testing phase

Needs you and real systems

I can't do this part alone: it needs real accounts and keys that you paste yourself, and sometimes a customer.
