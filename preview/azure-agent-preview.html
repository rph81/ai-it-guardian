Agent

What the Azure agent may do

azure_queryResource Graph, fixed queries only (about 25: public IPs, NSG rules, storage settings, SQL firewall, Key Vaults, VM disks and extensions, role assignments…), optional filter by subscription / resource group
azure_getManagement API GET on an allowlist of paths (Defender for Cloud, policy, diagnostics, backup, activity log alerts, locks)
record_findingAs today; resource ID as the asset

No write calls exist in the tool; Guardian never asks for a write role. Results are capped and passed to the agent as data.

Checks (CIS Microsoft Azure Foundations + Defender for Cloud)

What it reviews

Defender for CloudSecure score, open recommendations, plans switched off, alerts in the last 30 days
Internet exposurePublic IPs, VMs with RDP/SSH open to the internet, public load balancers, App Service without restrictions
NetworkNSG rules allowing any source, missing NSGs, flow logs off, DDoS plan
StoragePublic blob access, shared-key access, HTTPS only, minimum TLS, soft delete, private endpoints
DatabasesSQL / PostgreSQL / MySQL firewall open to Azure or all, auditing, TDE, Entra-only auth
Key VaultPurge protection, soft delete, public network access, expiring keys and secrets, RBAC model
ComputeUnencrypted disks, missing endpoint protection / updates (Defender), unmanaged disks, old VM images
Identity & accessOwners per subscription, guests or service principals with Owner/Contributor, custom roles with *, classic admins
LoggingActivity log retention / export, diagnostic settings on key resources, alerts for policy and NSG changes
ResilienceVMs and SQL without backup, no resource locks on critical resources, single-zone deployments
GovernanceAzure Policy assignments and non-compliant resources, untagged resources, unused public IPs / disks
Cost hygiene (info)Orphaned disks, IPs and NICs: small wins worth mentioning
Sample output

Findings as they'd appear

criticalP1RDP open to the internet on vm-jump01

NSG nsg-jump01 rule "AllowRDP" allows 3389 from Any; public IP 20.x.x.x. Fix: remove the rule, use Azure Bastion or Just-in-time access.

highP2Storage account stbackups01 allows public blob access

allowBlobPublicAccess = true; 1 container is public. Fix: disable public access at the account; use SAS or private endpoints.

mediumP3Key Vault kv-prod without purge protection

A deleted vault or secret can be purged at once. Fix: enable purge protection (can't be turned off again).

The Risk analyst ranks these with the rest, Attack paths can link them (e.g. exposed VM → managed identity → Key Vault), and Compliance maps them to the new CIS Microsoft Azure Foundations framework and to ISO 27001 / NIS2.

Decision for you

App registration

Reuse the Microsoft 365 app

Recommended for you: one app, one secret to rotate; just add the Azure roles to it.

Separate Azure app

Cleaner separation per customer (common for MSPs): a leaked M365 secret doesn't open Azure, and vice versa.
